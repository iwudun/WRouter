# 协议交换机制

> 蒸馏自 [reference/03 §2](../reference/03-网关协议与路由.md)（权威 file:line 在该处）；冻结契约见 `contracts/wrouter-capabilities.json`、`frontend/src/contracts/logs.ts`。本文讲机制与取舍，不重复契约清单。

## 1. 三个数据面与 passthrough

WRouter 是纯路由网关。客户端入口协议（7 值）× 上游协议（3 值）× `native_responses` 修饰，决定每个数据面是否原生透传：

| 数据面 | 原生同协议 | 实现 |
| --- | --- | --- |
| 请求体 | ✅（仅顶层 model 不同时定点 Patch） | `protocol/mod.rs::upstream_payload_impl_with_report` |
| 非流响应体 | ✅ | `protocol/mod.rs::try_decode_response` |
| 流式响应体 | ✅ 且执行器为 SSE（Raw + ByteExact，输出原字节） | `forward/stream.rs`、`forward/record_encoder.rs` |

passthrough 格（`protocol/mod.rs:399-410`）：

- `OpenAi × OpenAi` 仅在**非** native_responses 时透传；
- `OpenAiResponses × OpenAi` 仅在**是** native_responses 时透传；
- `Anthropic×Anthropic`、`Gemini×Gemini`、`GeminiStream×Gemini`、`OpenAiEmbeddings×任意` 透传；
- 命中 → clone 原值，**不经语义模型**，策略记 `native_passthrough`。

特例：`gemini_interactions` 请求走协议专项 helper（浅变换 `input`→`contents`，保留其余键），不经语义内核、不产报告；响应面仍走语义转换。

**边界**：非流客户端 + 流式上游不支持；`GeminiInteractions` 仅非流（`stream=true` 规划层拒绝）；上游 NDJSON 属注册的 NDJSON→SSE 表示转换，仍重建。

## 2. native_responses 判定

`provider.rs:579-587`：`protocol == OpenAi` 且 `protocol_style == "openai_responses"` 才 native。`protocol_style` 来自配置 JSON 的 `type` 键，**无枚举校验**（取任意非空字符串），只有 `openai_responses` 一值有特殊语义。

`effective_wire_protocol()`（`provider.rs:595-605`）在**请求落库时**写入 payload 键 `provider_protocol`（读取侧现算会随配置漂移）——这是吞吐隐藏思考分支的判据来源（见 [请求结束与吞吐计算.md §4.2](./请求结束与吞吐计算.md)）。

## 3. 保真等级与正文模式

保真等级（`protocol/contract.rs`）：

| 等级 | 承诺 |
| --- | --- |
| `ByteExact` | 未修改正文原字节保留；不承诺 TCP/HTTP chunk、TLS、头字段大小写一致 |
| `StructureExact` | JSON 值/顺序/存在性/身份引用一致；允许声明过的重序列化 |
| `SemanticEquivalent` | 异协议表达不同，但声明支持的内容/行为/生命周期等价 |

正文模式 `Raw | Patch | Translate | Unsupported`：同协议原生格 = `Raw + ByteExact`；跨协议 = `Translate + SemanticEquivalent`；`GeminiInteractions→Gemini` 请求面 `Patch`、响应面 `Translate`。表示转换由 `ResponseExecutor`（SSE / NDJSON / JSON / JSON→流合成）按实际可达路径选择。

## 4. 唯一规划入口

`protocol::contract::plan_exchange`（`RequestProfile` + 目标协议 + `native_responses`）出站前固定数据面模式。未知/不支持组合返回 `ContractViolation`，**不回退透传**。能力矩阵每项 ∈ `Native | Equivalent | Degraded | Unsupported`：`Refusal`/`MultiCandidate`/`MultiItemPart` = Equivalent，`Annotations` = Degraded，`ReasoningSignature`/多模态/有状态引用 = Unsupported（签名同协议 Raw 保留，跨协议不迁移）。

矩阵门禁 `ensure_combination_supported`（`semantic/adapter.rs:176+`）在**请求面与响应面都调用**（`protocol/mod.rs:399` / `:584`，G-7 已关闭）：embeddings × Anthropic/Gemini、interactions × 非 Gemini 硬拒绝（`unsupported_protocol_combination`，`NotRetryable`）；其余放行。

## 5. 转换策略四记号（枚举 vs 运行时）

`semantic/diagnostic.rs:13-22`：

| 记号 | 含义 | 运行时是否写报告 |
| --- | --- | --- |
| `native_passthrough` | 原生透传保真 | ✅ |
| `semantic` | 语义转换 | ✅ |
| `lossy` | 有损（须带诊断） | ❌ 无构造点 |
| `unsupported` | 明确拒绝 | ❌ 表现为抛错，不产报告 |

四记号是**枚举口径**，不是运行时取值集合（当前只有两种写入 `ConversionReport.strategy`）；外部契约仍声明四记号。

## 6. 无损基座（wire）

`wr-domain/src/wire/`：

| 类型 | 作用 |
| --- | --- |
| `RawRecord` | 完整原文 Bytes + 内容范围/分隔符/绝对偏移/来源/到达时间 + 共享 `RecordView` |
| `SseFramer` | 字节级 SSE，保留注释/id/retry/未知字段、CRLF/CR、多行 data、BOM、EOF 残片 |
| `NdjsonFramer` | 独立 LF/CRLF 行分帧，不按 SSE `data:` 语法解释 |
| `JsonView` | 共享解析视图，显式记录重复键路径/数值词法风险/深度/UTF-8 状态 |
| `WireLimits` | 单记录/尾部/累计/深度/诊断预算；超限为粘性硬错误，不静默截断 |

`Content-Type` 走 `resolve_response_representation`：只接受精确媒体类型（`text/event-stream`、`application/json`、`application/x-ndjson`/`application/ndjson`），不做子串匹配。

## 7. 流式控制链（SourceFacts → Delivery）

| 组件 | 当前行为 |
| --- | --- |
| `SourceFacts` | 一个上游帧只解码一次；内容/usage/finish/终态/快照可同帧共存，保留帧身份与来源 |
| `SourceObserver` | 独占统计/生命周期/usage 质量/已提交正文投影；Responses `sequence_number` 同域重放识别（同号同内容拒收、同号异内容/降序计冲突）+ 1 MiB 续写前缀上限 |
| `PreparedExchange` | 出站前固定 profile/操作/目标/请求与响应模式/保真；未知组合触达上游前拒绝 |
| `select_response_executor` | 响应头后只从已规划执行器选（SSE/NDJSON/JSON→流合成/JSON）；未知/错配媒体类型显式失败 |
| `Delivery` | 首帧入队前提交 HTTP 头；produced/queued/committed 分账；提交前错误返回真实状态，提交后只能用协议内错误/真实中断 |

`SourceObserver::committed_text()` 是断流续写的唯一 prefill 来源。

## 8. 适配器契约与 `fc_` id 不对称

- **三个 trait**（`semantic/adapter.rs`）：`InboundAdapter`（`decode_request` / `encode_response` / `encode_error`）、`OutboundAdapter`（`encode_request` / `decode_response`）、`OutboundStreamAdapter`（仅 `protocol`/`capabilities`，`decode_event` 已删除）。客户端目标编码统一在 `ClientStream`，不在适配器。
- **注册表**（`adapter.rs:150-171`）：非流入站按 `SourceProtocol` 分派到 `openai_chat` / `openai_responses` / `anthropic` / `gemini`（Interactions 用 `InteractionsInbound`，Embeddings 返回 `None`）；非流出站按上游协议恒有三实现；流式入站/出站只覆盖 OpenAi / Responses / Anthropic / Gemini。
- **能力声明**：非流适配器一律 `CHAT_NONSTREAM`，不声明 Stream；`ANTHROPIC_STREAM` 额外声明 `supports_prefill_continuation`（Anthropic assistant prefill 的官方续写语义，其它协议族没有）。
- **解码无状态**：跨事件去重不能放解码层，约束与落点见 [流式状态机.md](./流式状态机.md) §8。
- **`fc_` id 两面不对称**（易踩）：
  - 请求面 `function_call.id` **恒生成** `fc_<uuid>`，来源 id 只进 `call_id`（`openai_responses.rs:404-412`；id 缺失会被严格上游 400）。
  - 响应面 `responses_function_call_id` 保留已是 `fc_` 的来源 id，否则生成 `fc_<uuid>`（`responses_target.rs:438`）——响应面要配对上游 `call_id`，不能照搬请求面策略。
