# WRouter 技术设计（design）

本目录是 WRouter 的**模块级深度技术设计**：讲清关键机制「怎么实现的」——公式、状态机、边界条件、为什么这样设计。面向要改这些模块的开发者。

## 与邻居目录的边界

| 目录 | 回答什么 | 粒度 |
| --- | --- | --- |
| `../reference/` | 项目现在是什么、怎么用、怎么构建 | 广度手册（概览 + 契约清单 + file:line 权威定位） |
| `../planning/` | 为什么改、怎么改、实施记录 | 方案档案（带日期，完成后移 `archive/`） |
| `../LESSONS.md` | 踩过的坑（规则 + why + 证据） | 踩坑活文档 |
| **`./`（design）** | **关键机制怎么实现的** | **深度机制（公式 / 状态机 / 边界 / 取舍）** |

- reference 给「是什么 + 在哪」（概览与权威 file:line）；design 给「为什么这样 + 怎么算」（机制推导）。两者交叉链接，不复制。
- 冻结契约（协议矩阵、策略记号、事件词表、日志键）的**权威**仍在 `contracts/wrouter-capabilities.json`、`frontend/src/contracts/logs.ts` 与 reference/03；design 引用并解释，不另立权威。
- planning 的方案叙事（为什么改、P1–P5 进度）不进 design；design 只蒸馏**当前持久机制**。

## 写作约定

- 平铺存放，文件名用**中文短名**，**无日期前缀**（活文档，随代码更新；区别于 planning）。
- **暂不建子目录**：当前 8 篇，平铺仍是最省点击的结构。当文档数超过 ~10 篇、或出现稳定成簇的模块（≥4 篇同域）时，再按模块拆子目录并在各子目录放一个 README 索引；拆分时同步更新本清单与站内链接。
- 只写**当前机制**，不写实施进度叙事；历史去 `planning/archive/` 与 git。
- 每个关键主张带 `file:line` 证据；引用契约链接到权威源。
- 与代码冲突时以代码为准，并尽快修正本文。
- 公式/常量给出符号与取值，并指明实现位置。
