# 模型指纹检测机制

> 当前机制蒸馏自 [reference/04 §7](../reference/04-功能与兼容性.md)（概览与权威 file:line 在该处）。
> 数值内核唯一实现在 `backend/crates/wr-domain/src/fingerprint/`；运行入口在 `wr-server/src/admin/model_fingerprint*.rs`。
> 本文讲「怎么算、为什么这样算」，不重复探针 RPC 形状与管理面契约（留 reference/04 §7 与 `contracts/wrouter-capabilities.json`），也不展开供应商连通性探测/账号快照（另一主题）。
>
> **术语硬隔离**：本模块「模型指纹」= 用模型输出统计特征判定后端真实模型身份；与「客户端指纹」（出站 HTTP 头/TLS 伪装，`protocol/client_fingerprint`）无关，全程不复用 `clientFingerprint` 一词（`wr-domain/src/fingerprint/mod.rs:3-5`）。
> 内核无 IO、无 async，过 `wr-domain` 纯度守护（禁 tokio/axum/reqwest/rusqlite，`mod.rs:14-15`）。

## 1. 特征提取

探针让模型「凭第一反应给出 N 个 1..355 的整数」，解析数字序列后提两组特征。常量（`features.rs:24-36`）：

| 符号 | 取值 | 含义 |
| --- | --- | --- |
| `VALUE_MIN` / `VALUE_MAX` | 1 / 355 | 数字闭区间 |
| `DIMENSION` (D) | 355 | 边缘分布维度（每取值一维） |
| `ALPHA` (α) | 0.5 | Hellinger 平滑常数 |
| `ORDERED_BLOCK_WEIGHT` (w) | 0.25 | 有序块在融合分中的权重 |
| `MINIMUM_VALID_NUMBERS` | 80 | 单条回答接受所需最少数字 |
| `ORDERED_BLOCK_DIMENSION` | 4×16+10 = 74 | 有序块维度 |

- **解析**（`parse_numbers`，`features.rs:50-95`）：
  - 取**最长数字游程**；两数字间出现字母（Unicode `\p{L}`）则断游。
  - 区间外数字丢弃但**不**断游（断游只看分隔符里的字母）。
  - 等长并列取第一个（对齐 Python `max(key=len)` / JS `reduce(>)`，手写「严格大于才替换」，`features.rs:85-94`）。
- **边缘分布**（`hellinger_feature`，`features.rs:110-116`）：

  ```
  h_i = sqrt((c_i + α) / (Σc + α·D))      α = 0.5, D = 355
  ```

  平方和恒为 1（Hellinger 变换把计数映到单位球）。
- **有序块**（`ordered_block_feature`，`features.rs:133-151`）：
  - 序列按 `np.array_split` 切 4 段（前 `n%4` 段多一个，`features.rs:119-130`）。
  - 每段 16 桶直方图：桶宽 355/16，桶号 `floor((v-1)/355·16)`，初值 0.5，取 sqrt 归一。
  - 再加末位数字 10 桶（初值 0.5）；共 74 维，捕捉「位置/末位」结构偏好。
- **标准化**（`standardize`，`features.rs:154-163`）：总体标准差（ddof=0），尺度下限 1e-12。

## 2. 打分与融合

单条回答的分数由两项融合（`score.rs`）。边缘分布项管线（`score_counts`，`score.rs:69-91`）：

```
h → (x−mean)/scale → project_out(干扰基) → normalize → 与各模型中心点内积 → standardize
```

Python 侧对 nuisance 标准化两次，本实现保留同样两次调用以逐位对齐（`standardize` 幂等，仅差浮点噪声）。

- **有序块项**（`ordered_block_scores`，`score.rs:94-144`）：
  - 模板项 = 各环境中心点（`environment_centroids`）得分取最大后标准化。
  - 干扰项 = 投影掉干扰基后与中心点内积再标准化。
  - 二者 `0.5·模板 + 0.5·干扰` 融合再标准化（`score.rs:138-143`）。
- **融合**（`score_numbers_with_group`，`score.rs:167-171`）：

  ```
  fused = (1−w)·marginal + w·ordered      w = 0.25
  ```

  w 取自工件 `ordered_blocks.weight`（`bank.rs:340`）；w=0 时退化为纯边缘项（`score.rs:158-165`）。

**多样本聚合与归因概率**（`analyze_with_group`，`score.rs:243-266`）：

- 各模型分数取有效回答的**均值** `combined_scores`（`score.rs:243-251`）。
- 再 `softmax(β·score)` 出概率；`softmax` 减最大值防溢出（`features.rs:206-214`）。

**接受门槛**（`score.rs:202-241`）：

```
minimum = max(bank.minimum_valid_numbers, 80)
若 expected_count > 0:  minimum = max(minimum, ceil(expected_count · 0.55))
```

拒答/截断/解析为空计缺口（`ProbeDiagnostic`），不计样本；无任何有效回答返回 `Err`（`score.rs:236-241`）。

## 3. 温度标定与证据阈值

**β 网格搜索**（`fit_beta`，`bank.rs:558-587`）：在对数网格上最小化平均负对数似然。

| 常量 | 取值 | 位置 |
| --- | --- | --- |
| `BETA_MIN` | 0.05 | `bank.rs:58` |
| `BETA_MAX` | 12.0 | `bank.rs:56` |
| `BETA_GRID` | 801 | `bank.rs:60` |

`β = exp(ln0.05 + step·(ln12−ln0.05)/800)`；上界 12.0 与 ModelTrace 一致（实测会被触及，`bank.rs:556-557`）。
归因时按 `min(有效条数, 3)` 取校准档位的 β，缺档位回落 1.0（`score.rs:262-264`）。

**阈值由实测导出，非手写常量**（方案 X3）：

- 校准记录由分组交叉验证产生，准确率 `acc = 正确数 / 记录数`（`bank.rs:695`）。
- 同时落实测混淆矩阵（行=真实、列=预测，`bank.rs:609-627`）。
- 阈值取该准确率（混淆矩阵对角占比）的函数（`derive_thresholds`，`bank.rs:599-606`）：

```
τ_strong   = 1 − 0.5·acc        (保守:宁可漏报不可误报)
τ_moderate = 1 − acc
τ_margin   = max(1 − acc, 0.5)   (top1−top2 间距下限)
```

**四档判定**（`score.rs:358-375`）：

| 条件 | 档位 |
| --- | --- |
| `margin < τ_margin` | `insufficient`（弃权） |
| `top1 ≥ τ_strong` | `strong` |
| `top1 ≥ τ_moderate` | `moderate` |
| 其余 | `weak` |

无校准阈值时直接 `weak`（仍给结论，`score.rs:363`）。

## 4. 库构建

`build_bank`（`bank.rs:633-820`）流程：解析丢弃无数字回答（`prepare_rows`，`bank.rs:415-439`）→ 闭集至少 2 个模型（`bank.rs:645-647`）→ 拟合全局工件 → 三档校准 → 模型条目 → 按供应商分组工件。

- **完整环境**（`fit_robust_artifacts`，`bank.rs:184-213`）：只用「该环境下全部模型都出现」的环境拟合（`robust_ready`）；无完整环境时回落全部行。
- **干扰基自适应秩**（方案 X1，`compute_nuisance_basis`，`bank.rs:353-372`）：
  - 各环境偏移均值 → 去均值 → 右奇异主方向 → 按累计能量选秩。
  - `NUISANCE_ENERGY_THRESHOLD=0.95`、`NUISANCE_MAX_RANK=4`，秩 ≤ `min(4, 环境数)`（`bank.rs:40-42,366-370`）。
  - 替代 ModelTrace 硬编码 `rank≤2`（环境数变化时会欠/过拟合）。
- **challenge 整组留出防泄漏**（`calibration_records`，`bank.rs:448-523`）：
  - 按 `condition` 分组，只保留「全部模型都有」的探针（`bank.rs:464-469`）。
  - 对 `query_count∈{1,2,3}`（`bank.rs:658`）枚举组合，**同一 challenge 的全部回答同时留出**（`bank.rs:473-478`）。
  - 用训练集重拟合工件再给留出集打分；这是防同探针重复采样泄漏的核心防御。
- **校准不得静默回退**（`bank.rs:661-678`）：采集不完整 → 该档位 `fallback=true`、β=1.0、`cv_accuracy=None`、无阈值；**禁止**沿用上一版准确率冒充当前值。
- **供应商分组**（方案 X2，`bank.rs:759-791`）：每个 provider（≥2 行且 ≥2 模型）单独拟合一组工件存入 `groups`，检测时用该供应商的基抵消通道偏移。
- **重复收录拦截**（方案 X7）：
  - `find_duplicate` 以中心余弦距离 `< DUPLICATE_CENTER_DISTANCE=0.10` 判疑似同模型（`bank.rs:54,830-858`）。
  - 入库前由 `duplicate_model_reason` 调用拒绝（`model_fingerprint.rs:137-158,605-608`）。
  - 0.10 经真实库实测校准：不同模型最小距离 0.349、准复制 ≈0~0.05（`bank.rs:44-53`）；重复收录会让 top-1 概率塌到 0.5。

## 5. 确定性线代内核

`linalg.rs` 自实现（workspace 无数值 crate、离线不可达 crates.io，`linalg.rs:3-15`）：

- **Jacobi 特征分解**（`symmetric_eigen`，`linalg.rs:40-133`）：
  - 循环 Jacobi，旋转顺序固定 `p<q`、收敛阈值 `1e-13·Frobenius`、≤100 sweep。
  - **完全确定性**（同输入恒得同结果含符号），满足「用户库每次重建复现同一库」。
- **右奇异方向**（`right_singular_directions`，`linalg.rs:189-239`）：
  - 对 E×E 的 `offsets·offsetsᵀ` 做 Jacobi 拿左奇异向量与 σ²，再 `v = offsetsᵀ·u/σ` 还原右奇异向量。
  - E×E 比 D×D 快两个数量级（建库交叉验证要重复拟合几十次，`linalg.rs:183-184`）；退化判据 `σ ≤ σ₀·1e-8`。
  - 与 numpy SVD 子空间相同、基方向可异；打分只依赖投影后子空间故结论一致（`linalg.rs:12-15,178-184`）。
- **选秩与投影**：`adaptive_rank` 累计能量 ≥ 阈值即停（`linalg.rs:245-264`）；`project_out` 顺序正交投影掉基张成子空间（`linalg.rs:281-290`）。

## 6. 归因边界

- **闭集**：概率只在库内 `model_order` 上 softmax（`score.rs:197-199,275-297`）；库外模型会被归到最相似候选，故证据不足必须弃权。
- **显式弃权**（方案 X4）：`insufficient` 档 `prediction`/`prediction_name`/`family_prediction` 全置 `None`，**不显示具体模型名**（`score.rs:376-399`）。
- **单一套件**：内置参考库与 `modeltrace-v1` 已下线，探针固定为 `wrouter-v1`（随机化池，固定 seed 可复现，`probe.rs`）；用户库条目仍带 `probeSuite` 字段，历史 `modeltrace-v1` 数据不再解析。
- **家族级概率**：按 family 聚合候选概率，并给家族内条件概率（`score.rs:305-355`）；另附与汇总分布的 JS 相似度 `profile_similarity`（`score.rs:280-282`、`features.rs:184-203`）作旁证。

## 7. 运行入口

**两层库**（`mod.rs`、`model_fingerprint.rs`）：

| 层 | 来源 | 套件 | 用途 |
| --- | --- | --- | --- |
| L2 用户全局库 | 用户自建 | `wrouter-v1` | 全局闭集归因 |
| L3 供应商锚点 | 用户库内按 `provider_id` 取分组工件 | 同 L2 | `anchor` 结论，通道偏移抵消 |

- L3 结论：`analyze_with_group(..., Some(provider_id))`。
- 库为空或不足 2 个模型时不给结论，返回 `skipped` 说明。

**三档探针**（`ProbeTier::probe_count`，`probe.rs:31-37`）：快速 3 / 标准 12（默认，`model_fingerprint.rs:202-206`）/ 完整 36。

- 上限 `MAX_PROBE_COUNT=36`（`model_fingerprint_probe.rs:33`）。
- `max_tokens` 放大到 `PROBE_FINGERPRINT_MAX_TOKENS=4096`（300+ 整数约需 1200–2000 token，256 会截断，`model_fingerprint_probe.rs:26-30`）。

**计费但不写日志/账本**：

- 探针**不经过网关转发管线** → 不计路由规则、不写调用日志、不进费用账本（决策点 4，`model_fingerprint_probe.rs:9-14`、`model_fingerprint.rs:17-18`）。
- 但用真实供应商密钥直发上游（`model_fingerprint.rs:219-221,533-535`），**上游照常计费**（reference/04:97；同款连通性探针即「真实计费的模型请求」，`speedtest.rs:3-5`）。

**缺口与协议限制**：

- `finish_reason ∈ {length, content_filter, refusal, max_tokens, incomplete}` 计缺口不计样本（`model_fingerprint_probe.rs:112-117`）；HTTP 4xx/5xx 先于 JSON 解析判缺口（`model_fingerprint_probe.rs:234-242`）。
- Gemini 暂不支持，直接报错（仅 OpenAI / Anthropic 系，含 `openai_responses`，`model_fingerprint_probe.rs:313-320`）。
