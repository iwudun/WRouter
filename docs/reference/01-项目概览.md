# 01 · 项目概览

> 最后核验:2026-11-08(源码 v0.2.5;最新发布安装包 v0.2.3。master,Electron → Tauri v2 迁移已完成并合入 master)。面向第一次接触 WRouter 的读者;读完应能回答:WRouter 是什么、由什么组成、代码在哪、数据放在哪。

## 1. WRouter 是什么

WRouter(简称 WR,机器标识小写 `wr`)是**本地 LLM 路由网关**:在本地起一个服务,把 Claude Code、Codex、OpenCode 等编码客户端发来的模型请求,按供应商/聚合选择器转发到 OpenAI / Anthropic / Gemini 等各家 Provider,并提供协议转换、重试回退、成本节省(压缩/缓存/粘性)、用量统计与请求日志,全部数据留在本机。

- **参考项目**:claude-code-router(CCR)。WRouter 早期以其为参考重写,能力面与管理交互有借鉴,实现完全独立(纯路由网关定位,Agent/扩展类功能已裁剪,见 04-功能与兼容性)。
- **典型形态**:Windows 个人电脑桌面应用(**Tauri v2 桌面壳**,已取代 Electron);Linux 服务器(systemd 用户服务 / 纯后端进程,**无桌面壳**)。部署环境硬下限为 **glibc 2.28**(Rocky 8 / 麒麟 V10 一代),Linux 交付 musl 静态单二进制。

## 2. 三大组成

| 组成 | 技术栈 | 交付形态 | 职责 |
|---|---|---|---|
| backend | Rust 1.98.0(tokio + axum,workspace 6 crate) | 单二进制 `wr`(打包名 `wr-backend(.exe)`) | 网关转发、协议转换、路由/重试、管理 API、SQLite 存储 |
| frontend | React 18 + Vite 8 + Tailwind 4(唯一样式系统) | 静态资源(桌面壳 `bundle.resources` 带出 / systemd 服务托管) | 管理界面:Providers / 路由 / 调用日志 / 用量 / 网络 / 设置 |
| desktop/src-tauri | Rust(Tauri v2) | Tauri 桌面壳(唯一桌面壳,Electron 已退场) | **后端同进程**、窗口加载管理面、`window.wr` 桥接层(8 个桌面方法,业务方法由前端补 28 个)、Windows 自绘标题栏(min/max/close)+ 单实例 + 开机自启;NSIS 安装包 |

为什么后端是 Rust:目标环境 glibc 2.28 上,Python 交付受解释器与 C 扩展 manylinux 基线的多重软约束;Rust 可交付 musl 静态单二进制,把兼容性从软约束变成硬保证,同时消除 GC 尾延迟与 GIL 并发限制(详见原 01 方案 §1.1 与内部方案编号映射表,原文在 git 历史)。Python 后端已于 2026-08-30 退役删除。

```

├── backend/        Rust 后端(cargo workspace:wr-cli/wr-server/wr-app/wr-domain/wr-infra/wr-test-utils)
├── frontend/       React 管理界面(Vite 8 构建,产物 frontend/dist/)

```

## 4. 端口

| 端口 | 服务 | 说明 |
|---|---|---|
| 3460 | Gateway | 模型请求入口(`/v1/chat/completions` 等,见 03) |
| 3462 | Web 管理面 | REST + `/api/wr/rpc` + `/api/wr/events`(SSE),见 02 |

- 环境变量覆盖:`WROUTER_GATEWAY_PORT`、`WROUTER_WEB_PORT`。
- 3461(core)已随迁移期兼容网关退役移除(2026-09-01),不再出现在配置与状态字段;3463(proxy)仅作为状态字段兼容占位,**无监听**;3464(MCP)/3465(Agent)已随功能移除(方案归档原 10/11)。
- 开发模式另有 Vite dev server(默认在 5280–5299 中逐个探测,`WROUTER_VITE_PORT` 可指定),只服务前端热更新。

## 5. 数据与日志

| 项 | Windows | Linux | macOS |
|---|---|---|---|
| 数据目录 | `%APPDATA%/WRouter/data/` | `~/.wrouter/` | `~/Library/Application Support/WRouter/data/` |
| 日志目录 | `%APPDATA%/WRouter/logs/` | systemd journal（`journalctl --user -u wrouter`） | `~/Library/Application Support/WRouter/logs/` |

- 数据目录可被 `WROUTER_DATA_DIR` 覆盖;Linux 统一 `~/.wrouter` 使 GUI、systemd 服务、纯后端三种形态共享同一份数据(Provider/密钥不丢)。
- **开发态与运行态共用同一数据目录**:`npm run dev` 不再重定向到仓库内,debug 与 release 构建都读写上表路径。需要隔离时用 `WROUTER_DATA_DIR` 显式指向临时目录 —— 造测试数据(如 `seed-fake-usage.mjs`)前务必先设,否则会写进真实数据。
- 核心存储:数据目录下 **`config.sqlite`**(配置、密钥、路由、日志等 **18 张表**,见 02);管理面 token 在 **`auth_token`** 文件(首次启动生成)。
- 日志文件:桌面壳直接写入 `<日志目录>/backend.log`(stdout 同步输出),单文件 5MB 轮转、保留 9 个归档(`WROUTER_LOG_MAX_SIZE_MB` / `WROUTER_LOG_MAX_FILES` 可调);Electron 时代的 `electron.log` 已随退场移除。Linux 纯后端形态走 systemd journal。
- 升级/卸载不丢数据:Tauri NSIS 卸载只清程序文件/快捷方式/注册表,**不删用户数据目录**;RPM 卸载钩子同样保留数据目录。

## 6. 关键概念速查

| 概念 | 一句话 |
|---|---|
| Provider | 一个上游服务配置(base_url + api_key + 模型列表),存于 SQLite |
| `provider/model` 前缀 | 请求模型名可写 `某provider/某模型` 强制定向,大小写不敏感 |
| 成本节省 | 全局 token 压缩 / 响应缓存 / 会话粘性 / 前缀钉扎(设置页开关;20261101_02 T3 起规则引擎已下线) |
| 执行计划(execution plan) | 一次请求的 Provider 尝试序列,决定回退行为(off/retry/model-chain 三模式) |
| 管理面 RPC | 前端与后端的统一管理协议 `POST /api/wr/rpc`,30 个方法(白名单见 `contracts/wrouter-capabilities.json`) |
| 桌面方法 | 壳注入的 `window.wr` 上的 8 个跨运行时公共面(导出/更新状态/外链/语言/DevTools 等);**不进管理 RPC** |
| 服务控制 | 暂停/恢复网关面(关 3460)、退出应用、停止服务;通用能力,所有运行时都有(见 02 §5.1) |
| capabilities | 上述方法白名单;由 `scripts/validate-capabilities.mjs` 做 JSON ↔ 后端 RPC ↔ Tauri 桥接层**三方一致性**校验(另含前端业务桥 ⊆ JSON 子集检查) |
| SSE 事件流 | `GET /api/wr/events`,管理面实时推送(状态/日志/用量变化),替代轮询;停机时主动收流并补发 `service-stopping` 帧(见 02 §5.1) |
| 探针(probe) | Provider 连通性测试:真实发一次小请求,过 5 重判定门 |
| 数据目录覆盖 | `WROUTER_DATA_DIR` 优先于平台默认值,用于隔离测试数据 |
