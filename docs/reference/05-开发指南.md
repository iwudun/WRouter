# 05 · 开发指南

> 最后核验:2026-11-07。环境、命令、质量门、调试与陷阱速查。

## 1. 前置环境

| 依赖 | 版本 | 用途 |
|---|---|---|
| Node.js | ≥ 20(推荐 22) | 前端构建、Tauri CLI、脚本 |
| Rust | **1.98.0**(backend/rust-toolchain.toml 锁定,rustup 进目录自动切换) | 后端 + 桌面壳 |
| VS Build Tools 2022 + MSVC target | 仅 Windows | **桌面壳**默认 target `x86_64-pc-windows-msvc`;`rustup target add x86_64-pc-windows-msvc` |
| WinLibs MinGW | 最新(仅 Windows) | **后端 workspace**(windows-gnu 宿主)的 dlltool/as,构建脚本自动发现 |
| Python 3 | 3.8+ | 仅 `scripts/verify/` 工具(黄金回放、Mock 上游)需要,非运行时依赖 |
| Docker Desktop | 任意 | 仅 Linux 打包需要(见 06) |

后端 workspace(GNU 宿主)与桌面壳(msvc)是两套独立工具链,互不影响。Windows 下若 `python` 触发 Microsoft Store,请关闭"应用执行别名"或用 `py`。

## 2. 环境初始化与日常启动

```bash
npm run setup        # 一键初始化:根/前端/desktop node_modules + cargo 构建 wr(release)
                     # 幂等;--rebuild 重装;--no-backend / --no-frontend 跳过对应步骤
npm run dev          # 开发模式(vite + Tauri 壳),输出带前缀汇到一个终端
```

`npm run dev`(= `npm run dev:tauri`,同一个脚本)的两个进程:

| 前缀 | 进程 | 说明 |
|---|---|---|
| `[fe]` | Vite dev server | 端口由 `scripts/dev.mjs` 探测(5280–5299),**HMR 热更新**(WROUTER_VITE_PORT 可改) |
| `[tauri]` | `cargo run --manifest-path desktop/src-tauri/Cargo.toml` | Tauri 桌面壳;**后端同进程**跑在壳内(独立线程 + 独立 tokio runtime),**不 spawn `wr-backend` 子进程** |

要点:

- **不需要后端二进制**:`desktop/src-tauri` 是独立 Cargo 工程,`wr-server` 是 path 依赖 → 改 Rust 代码后重跑 `npm run dev` 即重建。
- **窗口 URL**:dev 形态加载 vite dev server(HMR,`/api` 由 vite 反代到 3462);生产形态加载 `http://127.0.0.1:3462/`(后端静态托管同一份 `frontend/dist`)。
- **端口独占**:Tauri 壳自己起后端并占用 3462/3460 → **不要同时跑第二个壳实例**(单实例插件会让它自行退出,但端口会被抢)。
- **dev 与发布态共用数据目录**:`npm run dev` 直接读写 `%APPDATA%\WRouter\data`(Linux `~/.wrouter`),不再按构建类型分流。造测试数据前先设 `WROUTER_DATA_DIR` 指到临时目录,否则会污染真实数据;多个 checkout 同时开发时也建议各设一个。
- **自绘标题栏**:Tauri v2 没有 `titleBarOverlay` 之类的等价 API → 壳侧 `decorations(false)` 去系统标题栏,前端自绘 min/max/close 三键。拖拽区用 Tauri 的 `data-tauri-drag-region` 属性(**不是** `-webkit-app-region`);按钮容器加 `data-tauri-drag-region="false"` 阻断拖拽。
- **窗口层命令不进 `window.wr`**:8 个 `desktopMethods` 是跨运行时公共面,窗口控制是壳层 chrome → 走 `window.__TAURI_INTERNALS__.invoke()` 直调 `wr_window_*` / `wr_sync_launch_at_login`(见 `frontend/src/lib/tauri-window.ts`)。
- **开机自启**:配置落在后端 `AppConfig.launchAtLogin`;壳启动时对账一次,前端保存配置后立刻通知壳同步 OS 登录项(`HKCU\...\Run`)。
- **工具链**:桌面壳默认 target 就是 msvc(`desktop/src-tauri/.cargo/config.toml` 的 `[build] target`,只影响这个独立工程;后端 workspace 仍是 GNU 宿主)。需要 VS Build Tools 2022 17.14.44 + MSVC 14.44 + Windows SDK 10.0.26100 + `rustup target add x86_64-pc-windows-msvc`;`@tauri-apps/cli` 2.12.4 装在 `desktop/`(`npm --prefix desktop run build`)。

分组件启动:`npm run dev:fe`(仅 vite)/ `node scripts/dev.mjs --no-app`(不启壳)。

## 3. 常用命令


## 5. 调试手段

- **日志**:桌面壳写入 `<日志目录>/backend.log`(目录见 01 §5;stdout 同步输出),Linux 纯后端走 systemd journal;统一行格式 `[时间] [backend] [等级] [模块]: 消息`(自定义 tracing formatter,`RUST_LOG` 控级别,缺省 info),5MB 轮转 × 9(`WROUTER_LOG_MAX_SIZE_MB` / `WROUTER_LOG_MAX_FILES` 可调)。
- **浏览器联调管理面**(不经桌面壳):后端开着静态托管时,**直接用浏览器打开 `http://127.0.0.1:3462/`** 即可 —— 前端经同源 `GET /api/wr/session` 自动取管理令牌(`/api/wr/session` 仅对 loopback 放行,非 loopback 访问 403,此时用 `?wr_web_token=<token>` 兜底,token 见 `<data_dir>/auth_token` 或 `WROUTER_WEB_AUTH_TOKEN`)。SSE 逐块透传,可测全链路。
  > 历史上的 drill server(`scripts/verify/archive/web_drill_server.py`,静态服务 + `/api` 反代)已随 20261016_02 归档清理从工作区移除;需要时从 git 历史取回。
- **DevTools**:仅 **dev 构建**可用;`window.wr` 是壳注入的桥,可直接手发 RPC。侧栏左下角原本的「开发」按钮已删(现为侧栏顶部 logo 右侧的「开发」**徽章**,只标识开发态、不承担 DevTools 入口职责)→ 用 webview 内置 DevTools:`cargo run` 后按 `Ctrl+Shift+I`,或临时调 `window.wr.toggleDevTools()`。
- **专项脚本**(`scripts/verify/`,说明见其 README):`replay_golden.py`(黄金回放一条命令)、`cases.py`(22 case 定义)、`mock_upstream.py`(Mock 上游)、`seed_config.py`(造配置数据)、`_capture_cases.py`(case 重采)。
- **VS Code 调试**:Tauri 壳是 Rust 工程,用 Rust Analyzer / `cargo run` 调试;webview 侧用 dev 构建的 DevTools。
- **SQLite 直查**:`sqlite3 <data_dir>/config.sqlite`,表清单见 02 §4。

## 6. 代码修改后的固定检查单

1. **改了 RPC(增删/签名)**:五点同步——contracts JSON、Tauri 桥接层(`bridge_core.rs`)、`types/desktop.d.ts`/web-client-bridge、后端 handlers、validate-capabilities;再跑质量门 #4。
2. **改了前端文案**:检查 i18n 两份词典;删键前做后端文本提取(错误消息会按后端文本查表翻译)+ 动态拼接键(`t(变量)`)人工排查。
3. **改了 Rust**:wr-domain 只进纯逻辑,新依赖先看纯度禁用清单;注意 `WR_VERSION` 不变则增量编译可能不重跑。
4. **任何"遗留/死代码"清理**:动手前重新 grep 查证——遗留清单不等于事实(历史教训,方案归档原 12/13)。

## 7. 版本号

唯一手改处是根 `package.json` 的 `"version"`(当前 **0.2.5**),其余由脚本同步:`npm run version:sync` 写入、`version:check` 只校验。同步范围(scripts/sync-version.mjs,**7 个文件 / 10 处**):`frontend/package.json`(1)、`package-lock.json`(2)、`frontend/package-lock.json`(2)、`frontend/src/pages/home/shared/fallbacks.ts`(1)、`desktop/src-tauri/tauri.conf.json`(1)、`desktop/package.json`(1)、`desktop/package-lock.json`(2);后端与桌面壳的版本经构建期 `WR_VERSION` 注入(编译期常量 `option_env!` —— **不注入会退化成 `0.0.0-dev`**)。注入点:`packaging/build-rust.sh`(后端产物)、`scripts/build-desktop.mjs`(Windows 安装包)、`scripts/dev.mjs`(开发态 `npm run dev` —— 漏注入则设置页「当前版本」显示 `0.0.0-dev`),三者都从根 `package.json` 读同一个版本;`scripts/sync-version.mjs --check` 会逐个校验注入点是否还在。

## 8. 高频陷阱

> 更完整的踩坑库(规则 + why + 证据)见 [`docs/LESSONS.md`](../LESSONS.md) —— 动手前先查它;踩到新坑顺手追加;同一条在 3 个不同日子重复出现即晋升进本表或 `AGENTS.md`。

| 陷阱 | 要点 |
|---|---|
| 行尾 EOL | 新文件一律 LF;`.ps1` 必须 **UTF-8 with BOM + CRLF**(PowerShell 5.1 对 LF 中文注释按 GBK 解析会炸);提交前 `git ls-files --eol` |
| 容器内脚本行尾 | 容器里跑的 `.sh` 必须是 **LF**。Windows 的 `WriteAllLines` 默认写 CRLF → 容器内 bash 报 `set: pipefail: invalid option name`(**报错信息极具误导性**,实际是行尾问题) |
| 容器内再调 docker | `smoke-test-linux.sh` 内部调 docker,不能直接在容器里跑它;要把容器内断言提取成独立脚本执行 |
| 脚本里写死版本号 | 升版后校验脚本会**假 FAIL**(期望值没跟着变)。`packaging/verify-installer.ps1` 已改为从**安装包文件名**推导期望版本,别再写死 |
| heredoc 反斜杠 | 经 PowerShell 通道的 heredoc 内 `\\` 会折半 |
| 鉴权 401 | 管理面除 health/capabilities 外都要 `x-wrouter-web-auth`;token 看数据目录 `auth_token` 文件 |
| 端口冲突 | 5280–5299(vite)/3460/3462;占用排查 `netstat -ano \| findstr <port>` |
| file:// 限制 | URL 型 Dedicated Worker 不可用,新 worker 一律 `?worker&inline` + CSP `worker-src 'self' blob:` |
| NSIS 工具链 | Tauri 的 NSIS 从 github.com 下载(本机 github.com 不达)→ 先跑 `packaging/fetch-tauri-nsis.ps1` 预置 |
| 桌面壳单测 target | 链了 WebView2 的 test harness 在 **GNU** 下起不来(0xC0000135/0xC0000139)→ 桌面壳测试必须 `--target x86_64-pc-windows-msvc`;纯逻辑用例已拆到 `--test pure_logic` |
| 浏览器 evaluate | 自动化里传字符串箭头函数不会执行,用 IIFE 表达式 |
| musl 产物域名解析 | musl 直查 DNS 无 nsswitch;企业内网改用 gnu.2.28 备选轨 |
| tracing 换行 | 自定义 formatter 换行符必须显式写,别换回默认 formatter(缺失会让 stdout LineWriter 永不刷新) |
| WSL 路径改写 | WSL 的 `bash` 会把 `E:\...` 改写成 `E:...`;调 docker 脚本用 `MSYS_NO_PATHCONV=1` + 纯 POSIX 路径 |
| git 输出当错误流 | `git` 的 stderr(如 `Switched to branch 'master'`)会被 PowerShell 当错误流 → `$ErrorActionPreference='Continue'` + 显式检查 exit code |
