# 04 · 功能与兼容性

> 最后核验:2026-11-07。描述当前能力边界;与 CCR 的功能收敛历史见方案归档(原 05/07/10/11)。

## 1. 与 CCR 的关系

WRouter 以 claude-code-router(CCR)为参考基线,是**纯路由 LLM 网关**定位:重写了路由/协议/管理面核心,裁剪了 Agent 会话、MCP 工具聚合(ToolHub)、系统托盘、Fusion/扩展页、Bot Relay、内置浏览器等外围(2026-08 三轮功能移除,commit 796cb9d / 9e07863 / c4f5122)。与 CCR 端口不冲突(3460/3462 vs 3456/3457)。

## 2. 功能矩阵

### 2.2 已移除(历史能力,勿再引用)

Agent 会话运行时、本地凭据导入、builtInRules/grok-subagent 硬编码策略、codex 限额 RPC、ToolHub/MCP 网关(端口 3464)、系统托盘、Fusion/扩展页、Bot Relay、内置浏览器,以及 Electron 桌面壳(已由 Tauri v2 取代)。

HTTPS MITM 代理与网络捕获也**已移除**:随前端 networking 页整体下线,Rust 后端本就无 MITM 引擎,相应 RPC(`getProxyNetworkCaptures` / `clearProxyNetworkCaptures` / `setProxyNetworkCaptureEnabled`)已从注册表删除;证书签发模块(`wr-infra/src/ca.rs`)保留但未接入数据面。

`wrouter://` 自定义协议深链**未实现**(代码里没有该 scheme 注册);当前只有 SPA fallback:管理面未知路径回落到 `index.html`,且 `/api` 下的 404 不被 fallback 吞掉。

### 2.3 未实现 / 已接受限制

OAuth 账户连接器、RBAC 多用户等未实现项已并入 [07 §2](./07-FAQ与已知限制.md) 的技术债登记(TD-13)。

## 3. api_key 三态语义

Provider 密钥写入语义(**不可回退,改动需特别谨慎**):

| 请求中的 api_key 值 | 行为 |
|---|---|
| 字段缺失 / 空串 / `***`(脱敏回显值) | **不改**现有密钥 |
| 显式 `null` | **清空**密钥 |
| 其它非空值 | upsert 新密钥 |

配套约束:管理接口(`getProviders`/`getConfig` 等)只返回脱敏值(`***`);密钥永不落日志、错误信息与导出。

## 5. 上游代理配置

出站请求(网关 → 各 Provider)可经代理转发,当前支持两种全局模式(`wr-infra` 出站代理模块):

| 模式 | 语义 |
|---|---|
| `none`(默认) | 直连 |
| `preset` + `presetId` | 引用设置页保存的命名代理预设(server/port/可选凭据) |

行为细节:

- **loopback 一律直连**:`localhost`、`127.0.0.0/8`、`::1`、`0.0.0.0` 不走代理(防自循环)。
- 供应商级覆盖仍支持 `direct` / `preset`;不提供内联自定义代理。
- 旧 `custom` / `system` 模式已退役(2026-11-07):配置中的旧值不再迁移,解析时按未知模式**直连**并记警告。
- 预设缺失、非法或指向 WRouter 自身端口时拒绝并降级直连。

## 6. 国际化与主题

- 语言:中文/English/跟随系统(`navigator.languages`),偏好存 localStorage `wr.ui.language`;后端返回的错误消息会按查表翻译成当前语言。
- 主题:跟随系统深浅色(CSS `prefers-color-scheme` + Tailwind `dark` 变体);Windows 桌面壳的标题栏配色由壳侧 `wr_window_apply_theme` 与前端主题同步。

## 7. 模型指纹检测

**是什么**:用模型输出的统计特征(数字边缘分布 + 有序块)判定后端真实模型身份 ——「这个号称 `gpt-5` 的上游,实际是谁」。**与「客户端指纹」(20261016_03)无关**:后者是出站 HTTP 头/TLS 身份伪装,两者术语硬隔离。

**入口**:供应商详情页「模型列表」标题行 →「检测模型指纹」;设置页「模型指纹库」分区管理指纹库。

**两层库**:

| 层 | 来源 | 用途 |
|---|---|---|
| L2 全局候选库 | 用户自建(采集入库) | 「这个供应商号称的 X 是不是 X」 |
| L3 供应商锚点 | 用户在该供应商下实测 | **最可靠** —— 按供应商单独拟合分组工件,抵消通道偏移 |

> 内置参考库(L1)已下线:它是 2026-10 的固定快照、跨通道效度未经确认,不再随包分发。首次使用需先自建库(至少 2 个模型)。

**探针**:向目标模型发「请给出 N 个 1..355 的整数」,解析数字序列。档位三档:快速 3 条 / 标准 12 条(默认)/ 完整 36 条。探针请求**不写调用日志、不进费用账本**,但**会产生上游计费**。

**证据强度**:strong / moderate / weak / insufficient 四档,阈值由库内交叉验证准确率导出。`insufficient` 档**不显示具体模型名**(显式弃权)。

> 特征维度、打分融合、β 温度标定、阈值公式与库构建(含 challenge 留出防泄漏)见 [design/模型指纹检测.md](../design/模型指纹检测.md)。

**已知限制**(详见设置页说明区):

- 闭集归因 —— 库外模型会被归到最相似候选;
- 中转站注入的 system prompt 会改变分布,带自定义 system prompt 的客户端不适合检测;
- 库的准确性取决于采集样本:每个模型至少 12 条(标准档),且需覆盖 12 个环境;
- Gemini 协议暂不支持指纹检测(仅 OpenAI / Anthropic 系)。

## 8. 数据格式与升级兼容(2026-11-07)

**只支持最新数据格式,不做自动迁移。** 升级前请完整备份数据目录(见 README「运行时数据与日志」)。

| 数据面 | 最新格式 | 旧格式处置 |
|---|---|---|
| 配置 JSON | `AppConfig::to_dict` 写出的权威键:`version` / `preferredProvider` / `Providers` / `APIKEYS` / `policies` / `reliability` / `savings` / `modelGroups` / `theme` / `launchAtLogin` / `proxy` / `observability` / `Router` | 旧 snake_case/别名键、provider 的 `base_url`/`baseUrl`/`apiKey`/`apikey`/`credentials` 不再读取;`icon` 不再丢弃、原样保留;加载时记一条低基数警告,不崩溃、不自动改写文件 |
| Provider 记录 | `api_base_url` / `api_key` / `accounts` | 旧键忽略;旧单密钥不再自动合成 `default` 账号 |
| 路由密钥白名单 | `供应商/模型` 或 `wrouter/<聚合名>` | 旧裸模型名/裸聚合名不再兜底匹配 |
| 代理 | 全局 `none` / `preset` | 旧 `custom` / `system` 不迁移,按未知模式直连 |
| 请求日志 | 主行轻量元数据 + `request_log_bodies` / `request_log_headers` / `request_log_attempts` 侧表 | 旧内嵌正文/采集不再并回;行仍可列出,正文按「不可用」降级;不删除历史行 |
| 用量统计 | 最新行含 `provider_protocol` 等字段 | 缺字段行按防御性缺省处理并参与聚合,不因旧行崩溃 |

**保留边界**:SQLite 表名/列名与 `CREATE TABLE IF NOT EXISTS` 建表方式不变;不 ALTER/DROP/重建表;不自动删除或回写历史行;卸载仍保留用户数据。
